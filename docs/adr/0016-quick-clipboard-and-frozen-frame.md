# ADR 0016: Quick Clipboard delivery and frozen-frame transport

Date: 2026-11-06. Status: implemented in the 1.7.0 development candidate; native acceptance limits are in ../VERIFICATION.md.

Quick Clipboard reuses the main WebView, temporarily taking a small pointer-monitor position and minimum size. Sidebar state and Pinned Mode stay independent; native bounds and constraints are restored on dismissal. A separate metadata query returns at most 40 previews without blob reads, full-text payloads, original-image decoding or archive counting. Search is serialized with one latest queued request, stale results are not pasteable, rendering is virtualized and quick browsing is capped at 200 Clips. Clear reuses the existing unpinned batch/Trash/Undo semantics.

A Paste Session captures the external window identity before activation and consumes one selection. Clipboard publishing reuses native text, PNG/DIB and staged-file adapters, including self-ingestion suppression. Cancellation is checked again at publishing. Input is dispatched once only after modifier release, destination and foreground identity checks, and matching clipboard sequence; failed focus or input is a copied/manual-paste outcome. Outside-click dismissal never restores focus. No Enter is sent and dispatch success does not establish that a destination accepted the payload.

Ordinary Win+V registration was rejected on the development PC. Optional takeover therefore uses a dedicated chord-only low-level hook; ordinary Quick Clipboard activation remains a separately conflict-checked registered shortcut. The hook passes unrelated keys and modified variants, ignores injected input, coalesces V repeat and queues UI work on its message thread. A non-character injected key prevents Start-menu activation after consuming Win+V. There is no driver, global remapping, Windows history disable or typed-content log. This deliberately extends the registration-only architecture: takeover stays off by default and experimental until physical remapper, release-order, dictation and Windows-build acceptance passes.

Screen snip keeps a bounded opaque top-down BGRA desktop frame in native memory and sends BMP through binary IPC only to the current capture overlay/session. This trades temporary raw-transfer memory for removing full-desktop PNG/base64 compression from selection startup; it does not promise lower peak memory on every desktop. The 32-megapixel bound remains. The frontend releases the transport URL after decoding and defers its undo baseline until markup. Unannotated Copy crops/encodes the native selection; annotated copies retain the existing document export. Clipboard readiness closes the overlay before bounded archival/preview work, whose failure is reported separately. Native DWM transitions are disabled per utility window without changing Windows settings; layout is measured before showing a selectable frame. The compositor-settling wait remains until a native replacement is verified.

The canonical ExcludeClipboardContentFromMonitorProcessing marker is now recognized alongside existing markers. A failing producer-adapter regression established the name mismatch; it is not evidence that a particular private item was collected. Original image data, legacy application identifiers and storage paths remain compatible.
